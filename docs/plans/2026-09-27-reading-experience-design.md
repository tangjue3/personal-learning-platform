# 书架与阅读体验第一阶段设计

## 目标

把个人学习平台从课程 Markdown 展示页推进为可日常使用的本地学习书架。用户能将一门课程中的多篇 Markdown 作为一本书管理，也能导入 EPUB 和 PDF；阅读位置、批注、笔记和导入文件留在本机。

## 产品范围

### 书架

- 继续支持课程目录、多篇 Markdown 文件导入，并保留课程内容在 `content/books/<稳定课程 ID>/` 的现有仓库规则。
- 支持 EPUB、PDF 电子书导入，书目在书架中统一搜索、分类和打开。
- 书架清楚呈现封面、书名、格式、阅读状态与进度，支持最近阅读和继续阅读。
- 对无效、重复或不支持的文件给出可理解的提示；导入被取消或失败时不留下半成品。

### 阅读器

- Markdown、EPUB、PDF 使用适合各自内容结构的目录与阅读定位方式。
- 自动保存每本书的最后阅读位置；离开后可继续上次进度。
- 支持舒适的文字宽度、字号、主题和专注阅读布局。
- 支持书签、文本高亮/摘录和关联笔记；笔记可回到对应章节或 PDF 页。
- EPUB/PDF 文件、私人书目、阅读进度和笔记保存在本地存储，不写入 Git 仓库。

## 数据边界

- 课程 Markdown 继续遵守 `AGENTS.md` 与 `content/books/README.md` 中的内容仓库规范。
- EPUB、PDF 二进制文件以及个人阅读数据留在被 Git 忽略的本地目录或浏览器本地数据库。
- 不增加加密口令、云端同步或登录流程。
- 现有书目和本机学习记录需继续可读；新增字段采用兼容性读取，避免初始化时重置已有记录。

## 阅读组件选择

- EPUB 使用 [epub.js](https://github.com/futurepress/epub.js)，从本地 Blob 加载并渲染目录和章节；脚本内容保持禁用，按其沙箱建议处理导入内容。
- PDF 使用 Mozilla 的 [PDF.js](https://mozilla.github.io/pdf.js/getting_started/) 显示层，阅读器自行提供符合本平台风格的页码、缩放和目录界面，并正确配置 worker。
- 具体版本和安装锁文件应在依赖安装通道恢复后一起确定，保证应用离线启动时无需从 CDN 下载阅读组件。

## 统一阅读记录

- 书籍使用稳定的 `bookId`；来源区分仓库 Markdown 课程和本机电子书，避免将 EPUB/PDF 路径或二进制内容混入课程仓库模型。
- 通用阅读进度记录包含 `bookId`、格式、最近阅读时间、完成比例与格式定位锚点。
- Markdown 定位到章节 ID 与标题锚点；EPUB 定位到 CFI；PDF 定位到页码，可选保存视口坐标。
- 通用阅读笔记包含书籍 ID、锚点、摘录、笔记正文、标签/颜色和创建/更新时间。不同格式只负责把通用锚点解析回页面或章节。
- EPUB 高亮可记录 CFI range；PDF 高亮在 PDF.js 文本层中记录页码和文本范围；Markdown 高亮以章节锚点、原文和前后文校验，减少课程内容更新后定位失效。
- 任何格式无法恢复锚点时保留笔记原文和摘录，并提示用户从原章节或页码附近查找，不自动删除记录。

## 实施顺序

1. 盘点现有书架数据模型和本机存储，明确 Markdown 课程与电子书的来源类型。
2. 完成 EPUB/PDF 导入、持久化、失败提示与书架呈现。
3. 按每种格式接入目录和阅读定位，打通继续阅读。
4. 完成书签、摘录批注及其与本机笔记的关联。
5. 手动检查常见成功、取消、失败和重启场景，确认个人数据未进入 Git 跟踪范围。

## 后续阶段

书架和阅读闭环稳定后，再把阅读计划、待办、日历、笔记和复习串入个人学习工作台，参考 Notion 的侧栏与视图组织方式，保持 Apple 简约风格。

## 验收标准

- 现有 Markdown 课程仍能导入、打开、按章节阅读，阅读进度不会因升级丢失。
- EPUB/PDF 成功导入后，刷新或重开应用仍可从书架打开。
- 三种阅读来源的阅读位置都能保存并恢复；书签或摘录可回到对应位置。
- 文件类型错误或解析失败时给出明确反馈，失败文件不会显示成可正常阅读的书。
- 个人文件与记录不进入 GitHub 可见的仓库内容。
