# 知序 · 个人学习空间

基于 Vue 3 的本机个人学习平台。课程内容由 Git 仓库管理；笔记、日程、待办、复习记录和阅读进度只保存在当前电脑。

## 功能页面

- 今天：学习天数、今日日程、待办和最近阅读
- 书架：把一门课程的多篇 Markdown 和本地图片导入为一本书；也可导入 EPUB 和 PDF；支持搜索、分类、排序和书籍管理
- 阅读器：Markdown、EPUB 和 PDF 使用各自的目录和定位；Markdown 支持代码块、表格、任务清单、提示块和相对图片；支持继续阅读、书签、字号、护眼配色和可返回原文的摘录笔记
- 日历：周视图和月视图，创建、编辑和删除日程
- 笔记：新增、编辑、搜索、关联书籍和章节，也可以从笔记制作复习卡
- 复习：创建知识卡片，按回忆结果安排下一次复习
- 课程同步：按需将仓库课程书籍同步到 GitHub，不包含个人学习数据

## 电子书文件位置

EPUB/PDF 原文件保存在项目本机目录 `data/local/ebooks/<书籍 ID>/` 下，由本机 Node 服务读写；浏览器不再保存电子书文件。此目录已加入 `.gitignore`，不进入 Git 仓库，也不会上传 GitHub。

单本电子书上限 512 MB。上传时浏览器把文件对象直接交给本机服务，服务端边收边写盘并重算 SHA-256，**服务端是全链路流式的，内存占用与文件大小无关**；文件不会转成 Base64，也不会写进 `records.json`。重复文件由服务端按自己算出的 SHA-256 判定并返回 409，因此导入前不需要在浏览器里先把整份文件读一遍。

需要如实说明的是：**浏览器端并不是全链路低内存**。浏览器端的 EPUB/PDF 结构预检和阅读器渲染都需要把整份文件读进内存，峰值约为文件大小的 2 倍（例如 100 MB 的 PDF 打开时约需 200 MB 堆内存）。因此：

- 超过 64 MB 的文件会跳过浏览器端结构预检，只保留服务端的文件头校验，打开时再由 EPUB.js/PDF.js 确认能否阅读；
- 文件越大，导入后的首次打开越慢、越占内存，这是当前实现的已知取舍；
- 阅读器通过 `/api/ebooks/<书籍 ID>/file` 一次性取回整份文件（该接口暂不支持 HTTP Range），所以 PDF.js 也无法分块流式加载。

## 数据位置和隐私

课程文档与图片放在 `content/books/<课程目录>/`，每本书由 `book.json` 描述，目录中的 Markdown 文件自动成为章节。课程文件存入当前 Git 仓库，可用 Git 管理和同步。GitHub 仓库如果是公开的，`content/books/` 里的内容也会公开；请勿在此放入私人资料。

日程、待办、笔记、复习卡、阅读进度、书签和阅读偏好保存在本机 `data/local/records.json`。此文件夹已加入 `.gitignore`，应用的 GitHub 同步只处理 `content/books/`。这些个人数据不加密、不上传 GitHub，也不会同步到另一台电脑。

导入的 EPUB/PDF 电子书原文件保存在本机目录 `data/local/ebooks/<书籍 ID>/`：原文件为 `source.epub` 或 `source.pdf`，同目录的 `book.json` 记录书名、作者、格式、文件大小和 SHA-256。该目录同样由 `.gitignore` 排除，不进入 Git 仓库、不上传 GitHub，也不会被复制进 `content/books/`。书籍 ID 保持不变，因此阅读进度、书签和笔记仍按原 ID 关联到 `data/local/records.json`。

右上角“数据与同步”提供两种备份方式：

- **本机快照**：同时保存 `records.json` 和 EPUB/PDF 原文件，放在 `data/local/backups/`；有个人数据时每天自动保存一次，最多保留最近 30 份。完整恢复前会先对当前数据创建安全快照，并明确提示本次恢复会替换个人记录和电子书；课程书籍不受影响。
- **记录 JSON**：便于单独导入导出的轻量备份，只包含个人记录，不包含 EPUB/PDF 原文件。导入时只补入本机缺少的记录，不覆盖已有内容；写入前也会自动创建本机安全快照。

备份恢复和记录导入导出需要本机数据服务在线。若服务未连接，请先在项目目录运行 `npm run dev:app`，重新连接后再从快照列表预览并恢复。

两类备份都只保存在本机并由 `.gitignore` 排除，不上传 GitHub。若需要防止电脑或磁盘损坏，可在平台关闭后将 `data/local/` 复制到私人外置存储；不要把其中的个人数据放进公开仓库。

早期保存在浏览器 IndexedDB 中的电子书，会在本机服务可用时自动迁移到 `data/local/ebooks/`：先复制文件并按大小和 SHA-256 校验，确认本机副本无误后才删除浏览器中的旧副本。迁移时按旧格式恢复阅读进度——PDF 的页码存为页码，EPUB 的位置存为 CFI，对象位置原样保留；只有 `data/local/records.json` 写入成功后才会删除对应的旧进度记录。本机服务未启动时不会迁移，也不会删除任何浏览器数据，旧书仍会出现在书架并标记为“待迁移 · 服务离线”，服务恢复后点书架上的“重试迁移”即可完成。迁移失败时浏览器原副本会被保留，书籍仍在书架显示，书架顶部会给出失败原因和“重试迁移”按钮。

为避免事件文件随阅读进度和编辑次数持续膨胀，下一次本机保存时会为每条记录保留最新状态与删除标记，移除可识别记录的旧版本；格式异常的条目会原样保留。

## 本地运行

需要 Node.js 22.13 或更新版本（PDF.js 运行要求）。

```bash
npm install
npm run dev:app
```

浏览器打开 `http://127.0.0.1:5174`。此命令会同时启动 Vue 页面和本机数据服务。平台只绑定本机回环地址。

正式启动前先生成前端文件：

```bash
npm run build
npm start
```

正式模式打开 `http://127.0.0.1:4173`。
